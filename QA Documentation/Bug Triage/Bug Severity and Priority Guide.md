# Bug Severity and Priority Guide

> Simulated portfolio guide.

## Severity
| Level | Meaning | Example |
|---|---|---|
| Critical | Prevents core use or causes severe instability | Game cannot launch |
| High | Major functionality is blocked or seriously degraded | Quest progression blocked |
| Medium | Important defect with workaround | Incorrect UI state |
| Low | Minor impact or cosmetic issue | Small visual clipping |

## Priority
| Level | Meaning |
|---|---|
| P0 | Immediate attention; release blocker |
| P1 | Fix as soon as practical; major player impact |
| P2 | Planned fix; moderate impact |
| P3 | Low urgency / polish |

## Severity vs Priority
Severity describes **impact**. Priority describes **urgency**.

A cosmetic issue on a highly visible launch screen could have Low severity but High priority. A severe issue affecting a rarely used feature may have High severity but lower priority depending on release risk.

## Triage Inputs
Consider reproduction rate, player impact, frequency, workaround availability, affected platforms, release timing and regression risk.
